Пользователь смотрит работающее приложение не на своей машине, а по внутреннему
адресу сервера, где идёт разработка (например `http://10.43.228.200:3000` —
строка «Network» в выводе `next dev`). Он подключается к нему из браузера на
другом устройстве.

Поэтому запущенный dev-сервер нельзя останавливать: если я убиваю процесс после
своих проверок (`pkill -f "next dev"` и подобное), пользователь просто теряет
доступ к приложению и вынужден спрашивать, что сломалось. Когда мне нужно
переключить ветку или иначе повлиять на запущенный сервер, сервер после этого
следует поднять снова и сообщить адрес вида
`http://<Network-адрес из вывода next dev>:3000`, а не оставлять пользователя
без работающего стенда.

Отдельные обходные пути (туннели, деплой, публикация статичного отчёта) уместны
только как дополнение, если пользователь сам просит показать результат вне
сервера: сетевой доступ по внутреннему адресу у него уже настроен и работает.
