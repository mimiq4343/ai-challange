# Day 33: проверка поддержки пользователей

Дата: 2026-10-18. Ветка: `day-33`, исходный `main`: `8a6996f`.

## Настоящие ответы

Проверено в браузере с настроенной серверной моделью `deepseek-v4-flash`,
реальными stdio MCP-вызовами и локальной E5. База знаний — два документа,
15 структурных чанков. Учётные записи и обращения вымышлены.

- **SUP-101, авторизация MCP.** Вопрос «Почему не работает авторизация?».
  Модель получила тикет, пользователя и документацию. Учла 403 только у
  защищённого планировщика, работающее обнаружение публичных инструментов,
  уже проверенную доступность и перезагрузку. Не назвала токен доказанной
  причиной, предложила локализовать источник 403 и проверить права/профиль.
  Ответ содержал пять использованных источников.
- **SUP-101, продолжение.** «Администратор уже проверил: токен совпадает.
  Какой следующий шаг, если 403 остался?». Ответ учёл новую проверку из
  переписки, не предложил повторять её, сохранил диагноз как неопределённый,
  предложил определить компонент, вернувший отказ. Четыре источника.
- **SUP-102, остановленный ответ.** Общий вопрос о причине проблемы и
  следующих шагах. Модель учла нажатую кнопку «Остановить», объяснила
  сохранение только завершённой пары, предложила повторный вопрос с ожиданием
  завершения. Два источника. Обновление страницы восстановило переписку.
- **SUP-103, новая инструкция.** Тот же общий вопрос дал другой ответ:
  проверить включение файла в корпус выбранного режима и переиндексацию;
  переформулирование уже пробовали, оно не обновляет индекс. Три источника.
  Модель не выдумала содержимое новой инструкции.
- **Вопрос вне продукта.** Вопрос о приготовлении борща с явным уточнением,
  что он не относится к тикету, дал «Не знаю: в базе знаний нет ответа» и
  уточнение по текущему обращению. Рецепт не сгенерирован.

После первоначальных длинных ответов промпт уточнён до 180 слов и трёх шагов.
Последующие ответы по SUP-102 и SUP-103 проверялись уже с этим ограничением.
Это инструкция модели, а не детерминированное ограничение числа слов.

## Интерфейс

Браузерный сценарий `tests/browser/support.mjs` прошёл на 1440×1000 для SUP-102
и на 390×844 для SUP-103: реальные инструменты, ответ с источниками, восстановление
после перезагрузки, возврат фокуса в поле, интерактивные цели не меньше 44×44 px,
без горизонтального переполнения. Мобильный выбор тикета работает с клавиатуры,
после выбора закрывается и возвращает фокус на заголовок списка.

Первый прогон нашёл реальную ошибку возврата фокуса: `focus()` вызывался до
применения `setBusy(false)` к отключённому textarea. Исправление возвращает
фокус эффектом после обновления React; повторный сценарий прошёл.
На мобильной ширине заголовок тикета вынесен в отдельную строку после визуального
осмотра. Также проверен drawer `/day-7`: открытие, Tab по кругу, Escape и
возврат фокуса на кнопку открытия без изменения существующих диалогов.

Независимое ревью обнаружило гонку ручного обновления с новой отправкой.
`tests/browser/support-refresh.mjs` воспроизвёл потерю нового обмена в интерфейсе,
когда задержанный GET обновления возвращался после успешного POST и GET новой
истории. Проверка поколения запроса теперь отклоняет такой устаревший результат.
Повторный сценарий прошёл с `delayedRefreshIgnored: true`.

## Границы проверки

Порог сходства E5 откалиброван по нескольким запросам. Он не является
семантическим доказательством: при 0.78 вопрос о борще получил фрагменты со
сходством 0.782; выбранный порог 0.82 убирает их. В ответах проверяются наличие
свежего контекста, допустимые ссылки и отказ при пустом поиске, а не корректность
каждого вывода модели. Реальные ответы не редактировались для отчёта.

JSON-MCP и HTTP API рассчитаны на учебные данные. Внешняя CRM, запись в тикеты,
аутентификация и права операторов не реализованы и не заявляются работающими.
