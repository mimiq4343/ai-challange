## Реальный прогон E5 и LLM

В отдельной временной копии репозитория заменено условие подготовленного
запроса в `src/lib/conversation-store.ts:308`:

```diff
-      WHERE id = ?
+      WHERE ? IS NOT NULL
```

Изменение закоммичено только в этой копии. Через локальный режим CLI выполнен
полный путь: Git diff и blobs, чанкинг, локальные эмбеддинги, запись SQLite,
retrieval, запрос к настоящей `deepseek-v4-flash`, валидация ответа и Markdown.
После проверки временная копия и её отчёты удалены.

Получено:

- 274 файла документации и кода из точного base SHA;
- 3825 структурных чанков E5, векторы размерности 384;
- три фрагмента документации и пять фрагментов кода в запросе модели;
- один успешно проверенный файл, ноль пропусков, код завершения CLI — 0;
- одно замечание категории `bug`, важность `high`, строка 308:
  «deleteConversation теперь удаляет все диалоги сразу».

Модель верно объяснила, что связанный ненулевой параметр делает предикат
истинным для каждой строки, а не выбирает один `id`, и предложила вернуть
`DELETE FROM conversations WHERE id = ?`. Она также отметила, что метод
может сообщить об успехе удаления отсутствующего ID, если удалены другие строки.

Найденные источники включали `docs/architecture.md`, README, маршрут
`src/app/api/conversations/[id]/route.ts` и связанные chat-agent модули.
Строка замечания прошла структурную валидацию. Само замечание основано
на diff, его `sourceIds` пуст.

## Ограничения измерения

Это один намеренно внесённый баг, без оценки полноты и точности на реальных
PR. Он подтверждает работу пайплайна с настоящими эмбеддингами и LLM,
а не доказывает, что RAG улучшил качество: сравнение с режимом без RAG
не проводилось.

Все пять выбранных фрагментов кода содержали только imports. Модель сослалась
на RAG-фрагмент при рассуждении о вызывающем маршруте, хотя тот не показывал
реализацию обработчика. Это утверждение нельзя считать подтверждённым.
Основной вывод о SQL следует непосредственно из diff и полного файла.
Масштаб каскадного удаления модель обозначила как ограничение: определения
внешних ключей не попали в выбранный контекст.

По результату этого прогона выдача кода для обычных правок исключает AST-чанки
`ImportDeclaration` и `ImportEqualsDeclaration`; при переименованиях они
сохраняются для поиска зависимостей от старого пути. Регрессионный тест
воспроизвёл выдачу imports до исправления и проходит после него. Полный
LLM-прогон после этого изменения не повторялся; переносить результат
предыдущего прогона на качество новой выдачи нельзя. Позднейшие исправления
якорей удаления/переименования и бюджета комментария также проверены
автоматическими регрессионными тестами без повторного полного LLM-прогона.

В одном слове ответа появились символы U+FFFD. Причина не установлена;
валидный JSON и UTF-8 не гарантируют отсутствия таких символов в самом
ответе провайдера. Общий потоковый агент не менялся.

Живой запуск Actions и запись комментария GitHub ещё не проверены:
workflow отсутствует в `main` и требует отдельно согласованного слияния.
PR для проверки не создавался. Публикация проверена контрактными тестами
с подменой HTTP: создание, обновление, пагинация, устаревшие SHA, закрытый
PR, ошибка 403 и таймаут. Значения ключей и сырые ошибки провайдера не выводились.
