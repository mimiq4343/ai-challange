# Day 12: персонализация ассистента

## Цель

Добавить поверх модели памяти Day 11 явный профиль пользователя: описанные
предпочтения по стилю, формату и ограничениям, подключение профиля к каждому
запросу и наблюдаемая разница ответов между профилями.

Ветка `day-12` создана от `main`, где уже собраны дни 1–11. Все прежние
маршруты продолжают работать.

## Утверждённые решения

- Профиль владеет своей долговременной памятью: `memory_long_term` получает
  `profile_id`, уникальность становится `(profile_id, kind, key)`.
- `/day-11` после миграции работает с LTM активного профиля. Две несовместимые
  семантики LTM в одном приложении не вводятся.
- Предпочтения структурированные: валидируемые поля плюс свободный список
  ограничений.
- Роутер памяти получает третий слой `profile` и обновляет предпочтения
  автоматически; каждая запись попадает в журнал с причиной и откатывается
  вручную.
- Разница между профилями показывается переключателем профиля в чате, без
  отдельного A/B-прогона.
- Активный профиль — серверное состояние, а не выбор в браузере.

## Модель профиля

`memory_profiles`:

| Поле | Значения |
| --- | --- |
| `name` | уникальное имя профиля |
| `role` | свободный текст, например «backend-инженер», может быть пустым |
| `tone` | `neutral`, `friendly`, `formal`, `direct` |
| `verbosity` | `brief`, `balanced`, `detailed` |
| `format` | `prose`, `bullets`, `table`, `code_first` |
| `language` | `ru`, `en`, `auto` |
| `expertise` | `beginner`, `intermediate`, `expert` |
| `active` | ровно один активный профиль, частичный уникальный индекс |

`memory_profile_constraints` — свободные ограничения профиля: `value`,
`origin` (`router` | `user`), `reason`, `UNIQUE (profile_id, value)`.

## Миграция Day 11

SQLite не меняет STRICT-таблицу на месте, поэтому `memory-schema.ts` выполняет
идемпотентную миграцию в одной транзакции:

1. создаёт профиль «Основной», если профилей нет;
2. пересоздаёт `memory_long_term` с `profile_id NOT NULL` и уникальностью
   `(profile_id, kind, key)`, переливая существующие записи в этот профиль;
3. пересоздаёт `memory_writes` с `CHECK (layer IN ('working', 'long_term',
   'profile'))`, сохраняя журнал.

Схему памяти теперь создаёт один модуль; `SqliteMemoryStore` и
`SqliteProfileStore` только выполняют запросы.

## Промпт

Порядок блоков: `system → профиль → LTM → WM → окно STM → запрос`.

```text
Профиль пользователя: Инженер (backend-инженер)
Отвечай кратко, тон прямой, формат — списки и код, язык русский, уровень эксперта.
Ограничения: без эмодзи; не извиняйся.
```

`MemoryLayerTokens` получает `profileTokens`; телеметрия под полем ввода
показывает сегмент `PROF`. Четвёртый тумблер отключает слой: блок не уходит в
промпт и стоит ноль токенов.

## Автоматический учёт

Роутер памяти принимает записи вида

```json
{ "layer": "profile", "kind": "tone|verbosity|format|language|expertise|role|constraint", "value": "...", "reason": "..." }
```

Значения полей проверяются по перечислениям; неизвестное значение отбрасывается,
`constraint` принимается как текст. «Отвечай короче» меняет `verbosity` на
`brief`, «без кода» — `format` на `prose`, «не используй эмодзи» добавляет
ограничение.

## API

```text
GET    /api/profiles
POST   /api/profiles
PATCH  /api/profiles/:id
DELETE /api/profiles/:id
POST   /api/profiles/:id/activate
POST   /api/profiles/:id/constraints
DELETE /api/profiles/:id/constraints/:constraintId
POST   /api/conversations/:id/personalized-messages
```

Удаление активного профиля активирует следующий по имени; последний профиль
удалить нельзя. Ответ `personalized-messages` добавляет заголовок
`X-Memory-Profile` к заголовкам Day 11.

## Интерфейс `/day-12`

- Правый rail: новая секция `ProfilePanel` (селектор профиля, создание и
  удаление, редактор полей селектами, список ограничений, тумблер слоя) и ниже
  существующий `MemoryInspector` Day 11 без копирования кода.
- Строка телеметрии под полем ввода дополняется сегментом `PROF`.
- Русский интерфейс, визуальная система Flash Chat, области минимум 44×44 px,
  видимый focus, без горизонтального overflow, bottom sheet на мобильных.

## Проверка

- `npm run test:profiles` — миграция старых записей в профиль по умолчанию,
  единственный активный профиль, каскад ограничений и LTM, изоляция памяти между
  профилями, разбор profile-записей роутера, порядок блоков и нулевой вклад
  выключенного профиля, смена профиля в агенте.
- Регресс: `npm run test:memory`, `test:persistence`, `test:tokens`,
  `test:compression`, `test:context-strategies`.
- Живой сценарий: профили «Инженер» (кратко, код, эксперт, без эмодзи) и
  «Новичок» (подробно, проза, начальный уровень); один и тот же вопрос под
  каждым профилем; фраза «отвечай короче» меняет `verbosity` автоматически.
