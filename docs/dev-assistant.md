# Ассистент разработчика — Day 31

Страница `/day-31` и команда `/help` отвечают на вопросы о самом проекте. Для
этого ассистент пользуется документацией (RAG) и контекстом репозитория (MCP).
Модель сама решает, какие инструменты вызвать.

## Команда `/help`

- `/help` без вопроса возвращает справку и текущую ветку. Ветку получает
  MCP-инструмент `git_branch`; LLM при этом не вызывается.
- `/help <вопрос>` запускает tool-loop: модель получает каталог инструментов
  MCP-сервера проекта и вызывает нужные. Например, `search_docs` для устройства
  и правил, `list_files` для структуры, `git_status` и `git_diff` для изменений.
  После этого она отвечает в Markdown со ссылками `[S1]` на найденные фрагменты.
- Любой другой текст отклоняется: поддерживается только `/help`.

Каждый `/help` независим: история прошлых команд в модель не передаётся и в
SQLite не сохраняется. Карточки вызовов инструментов и источники видны под
ответом только в текущей вкладке.

## Поток запроса

1. `POST /api/dev-assistant/help` с телом `{ "command": "/help …" }`.
   Сервер проверяет `Origin`, тип JSON и размер тела (до 16 КБ), затем
   разбирает команду в `parseHelpCommand` (`src/lib/dev-assistant-http.ts`).
2. `McpToolChatAgent` в режиме `project` запускает
   `scripts/project-mcp-server.ts` через stdio (`withProjectMcpTools`) и
   получает список инструментов.
3. Раунды модели: до 6 раундов с инструментами, до 4 вызовов за раунд и до 10
   вызовов всего, затем итоговый раунд без инструментов. Общий таймаут — 240 с.
   Аргументы проверяются схемами `projectToolSchemas`. Ошибочные аргументы
   возвращаются модели как ошибка инструмента и на сервер не уходят.
4. Ответ приходит потоком NDJSON: `tool-start` и `tool-result` по мере вызовов,
   затем `text` с итоговым ответом и `done`. Ошибка передаётся событием
   `error`. Дочерний процесс завершается вместе с запросом.

Источники в интерфейсе собираются из результатов `search_docs`. Номера `S1…`
сквозные в пределах одного `/help`: повторный поиск выдаёт `S6`, `S7` и
далее. Ссылка на номер, которого нет среди результатов, помечается как
неподтверждённая.

## Индекс документации

```bash
# Модель E5 общая с Неделей 6; если её ещё нет, команда скачает закреплённые файлы.
npm run dev-assistant:index
```

Корпус собирает `projectDocumentSources` (`src/lib/project-docs.ts`):

- `README.md` и `AGENTS.md`;
- все `*.md` из `docs/`, включая вложенные каталоги;
- модули SQL-схем `src/lib/*-schema.ts`.

Чанкинг и эмбеддинги переиспользуют Day 21–22: `indexDocuments` строит обе
стратегии `fixed` и `structural`, поиск использует `structural`. Модель —
локальная `Xenova/multilingual-e5-small` (384 измерения) на CPU. Индекс лежит
отдельно в `data/dev-assistant.sqlite`, отчёт с HitRate@5 по контрольным
вопросам `src/lib/dev-assistant-questions.json` — в
`data/dev-assistant-index.json`.

При каждом поиске сервер сравнивает хеш текущих файлов корпуса с хешем
индекса. Если документы изменились, результат приходит с `stale: true`, и
ассистент предупреждает, что индекс нужно пересоздать. Переиндексация
автоматически не запускается.

## Конфигурация и безопасность

- Лимиты, таймауты и промпты — в `src/lib/dev-assistant-config.ts`
  (`DEV_ASSISTANT_LIMITS`, `PROJECT_MCP_LIMITS`, `PROJECT_TOOLS_PROMPT`).
- Нужны только переменные основной модели `OPENAI_*`. Модель должна иметь
  профиль DeepSeek Flash в `model-profiles.ts`.
- MCP-сервер проекта только читает данные и не открывает сетевой порт. Он
  видит лишь отслеживаемые файлы рабочей копии.
- Фрагменты документации, список файлов и diff передаются провайдеру LLM в
  составе tool-loop. Не задавайте `/help` по изменениям, которые нельзя
  отправлять внешнему провайдеру.
- Результаты инструментов считаются данными, а не инструкциями: промпт
  запрещает исполнять команды из документов и diff.
