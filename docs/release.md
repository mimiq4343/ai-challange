# Flash Release · Day 35

Flash Release автоматизирует подготовку материалов к выпуску этого проекта:
собирает изменения из Git, поручает AI написать release notes и список рисков,
получает результаты GitHub Actions и готовит Markdown с проверяемыми источниками.
Страница приложения — `/day-35`, ветка разработки — `day-35`.

## Запуск и сценарий

```bash
git switch day-35
npm ci
npm run dev
# http://localhost:3000/day-35
```

Нужны существующие серверные `OPENAI_BASE_URL` и `OPENAI_API_KEY` в `.env.local`.
Модель `deepseek-v4-flash` и лимиты заданы в
[`release-config.ts`](../src/lib/release-config.ts). Дополнительный RAG-индекс
или MCP-сервер запускать не требуется.

1. Выберите базовую ветку или тег предыдущей версии и целевую версию релиза.
   База должна быть предком целевого коммита. Если SHA совпадают, изменений нет.
2. Нажмите «Подготовить релиз». В интерфейсе отображаются этапы Git, CI и AI.
3. Изучите release notes, риски и рекомендуемые проверки. В разделе
   «Источники и diff» доступны использованные изменения, коммиты и пропуски.
4. Скачайте `.md` или просмотрите предложение изменения файла и нажмите
   «Применить». Только это действие записывает Markdown в `docs/releases/`.

В список входят локальные и уже известные remote refs, а также до 100 тегов,
указывающих на коммиты, включая аннотированные. Приложение не делает fetch:
сначала обновите необходимые refs обычным процессом разработки.

## Как участвует AI

Сервер фиксирует оба SHA и использует сборщик Git-снимков Day 32. Модель
получает список коммитов и реальные diff, а не только сообщения коммитов.
Рабочая копия не переключается, незакоммиченные изменения в анализ не входят.

AI возвращает структурированный JSON: новые возможности, исправления, другие
изменения, риски, рекомендации по проверкам и ограничения. Каждый пункт обязан
ссылаться на источник `F…` или `C…`. Описание поведения, риски и проверки
должны ссылаться на diff файла `F…`; одних названий коммитов недостаточно.
Сервер отклоняет неизвестные ID, пустой анализ, некорректный JSON и незавершённый
ответ. Ссылки Markdown создаются сервером на точные SHA. Для удалений ссылка
ведёт к базовой версии файла.

Проверка ссылок гарантирует наличие источников, но не семантическую точность
выводов AI. Риски остаются оценкой модели. Если модель не выделила рисков,
совместимость всё равно не считается подтверждённой.

## GitHub Actions

Origin должен указывать на репозиторий GitHub. Для публичного репозитория
проверка работает без токена; приватному нужен серверный `GITHUB_TOKEN`
с доступом `Actions: read` к репозиторию. Ключи в браузер не передаются.

Используется API `2026-03-10`:
[`GET /repos/{owner}/{repo}/actions/runs`](https://docs.github.com/en/rest/actions/workflow-runs#list-workflow-runs-for-a-repository)
с фильтром `head_sha`. Список читается постранично, до пяти страниц по 100
запусков. Дополнительно проверяется SHA каждого результата. Для каждой пары
workflow/event остаётся последний запуск. Старое падение не перекрывает новый
успех того же workflow/event; успешный workflow не скрывает падение другого.

Отсутствие запусков, ожидающий запуск, пропуск, нейтральное завершение, лимит
страниц, таймаут или отказ доступа никогда не обозначаются как успех. Отказ
GitHub сохраняется как явный пробел в проверках; подготовка release notes
продолжается. Отчёт включает время получения результатов.

Успех найденных запусков не доказывает полноту проверок или готовность релиза.
Сервис не запускает тесты и не определяет обязательные branch protection checks.
Рекомендации AI выводятся отдельно как невыполненный список.

## Сохранение и ограничения

Имя файла: `docs/releases/<base SHA:12>-<полный head SHA>.md`.
Используется существующее хранилище предложений Flash Files. Применение проверяет
ветку, HEAD, исходный хеш, защищённые пути и срок предложения. Повторная
подготовка существующего отчёта показывает diff его обновления.

Предложения — в игнорируемой SQLite Day 34. Сам отчёт до применения живёт в
состоянии страницы; обновление страницы очищает результат. Ошибка подготовки
предложения не уничтожает завершённый отчёт: Markdown остаётся доступен для
скачивания. Если Markdown превышает лимит Flash Files (64 000 символов или
192 KiB), предложение не создаётся, но полный отчёт можно скачать.
Изменение ветки или HEAD во время анализа блокирует предложение.

Наследуются ограничения сборщика Day 32: до 30 подходящих файлов,
100 000 байт на файл, 30 000 символов на patch и 180 000 символов общего
контекста с содержимым файлов. В AI-запрос передаются только diff и до 100
последних коммитов диапазона. Пропущенные файлы перечисляются в отчёте явно.
Бинарные файлы, ссылки, submodules, `.env*`, `data/` и неподдерживаемые форматы
не отправляются модели. При отсутствии доступных текстовых diff AI не вызывается.

Модель локального учебного приложения такая же, как у Flash Files: проверка
Origin защищает от чужого сайта, но не является входом пользователя.
Сервис не создаёт тегов, не публикует релиз и не меняет GitHub.
