# Ассистент поддержки · Day 33

Страница `/day-33` — Flash Support: ответы по документации Flash Chat с учётом
пользователя, диагностики и предыдущих действий в тикете. Данные учебные,
помечены в интерфейсе и не являются реальной CRM. Тикеты и их статусы доступны
только для чтения. Ассистент не создаёт задачи и не меняет настройки.

## Запуск

Используется настроенный на сервере OpenAI-совместимый провайдер и модель
DeepSeek Flash, как в MCP-агенте Day 31. Значения ключей остаются в `.env.local`.
Новые зависимости и отдельный сетевой MCP-сервис не нужны.

```bash
git checkout day-33
npm ci
npm run support:index
npm run dev -- --hostname 0.0.0.0
```

Индексация проверяет и при необходимости загружает закреплённую локальную E5.
После изменения [FAQ](support/faq.md) или [инструкций](support/troubleshooting.md)
повторите `npm run support:index`. Индексы других дней не изменяются.
Неактуальный или отсутствующий индекс не подменяется знаниями модели: обмен
завершается ошибкой без сохранения. Политика отказа и релевантность регулируются
в `src/lib/support-config.ts`, значения секретов туда не помещаются.

## Данные и MCP

`src/lib/support-fixtures.json` содержит вымышленных пользователей и тикеты.
JSON проверяется по строгим схемам: обязательные поля, уникальность ID и
принадлежность тикета существующему пользователю. Он не содержит секретов.
Для изменения сценариев редактируйте этот JSON, сохраняя формат и `demo: true`.

Каждый запрос создаёт stdio MCP-сессию через
`scripts/support-mcp-server.ts <root> <ticketId>`. Модель сама выбирает инструменты:

- `get_ticket(ticketId)` — диагностика и история обращения;
- `get_user(userId)` — пользователь и его окружение;
- `list_user_tickets(userId)` — другие тикеты того же пользователя;
- `search_knowledge(query, limit?)` — семантический поиск по базе знаний.

Сервер ограничивает доступ пользователем выбранного тикета независимо от
аргументов модели. Секреты LLM не передаются дочернему процессу. В каждом ответе
обязательны свежие результаты текущего тикета, пользователя и поиска. Невалидные
аргументы возвращаются модели для исправления в пределах заданного бюджета.

Поиск использует отдельный SQLite-индекс и порог сходства. Источники получают
уникальные ID в пределах запроса. Сервер отклоняет неизвестные ссылки и ответы
без обязательного контекста; при пустом поиске требует «Не знаю» и уточнение.
Наличие корректной ссылки не является автоматической проверкой смысла ответа.

## Переписка и API

- `GET /api/support/tickets` — учебные тикеты;
- `GET /api/support/tickets/:id` — тикет, пользователь и сохранённая переписка;
- `POST /api/support/tickets/:id/messages` — `{ content, expectedCursor }`.

`expectedCursor` — ID последнего обмена или `null` для пустого диалога. История
и контекст загружаются на сервере: передать их в POST нельзя. Устаревшая вкладка
получает HTTP 409 до генерации; повторная проверка курсора внутри транзакции
защищает от конкурентной записи после начала генерации. История последних шести
обменов передаётся модели, вся переписка доступна в интерфейсе. Учебный лимит —
50 обменов на тикет.

NDJSON-поток содержит `tool-start`, `tool-result`, `text`, затем `done`.
Обрыв без `done` — ошибка. Полностью завершённый и проверенный обмен вместе со
снимками использованных источников записывается одной транзакцией в
`data/support.sqlite` перед `done`. Ошибка модели, MCP или отмена до записи
ничего не сохраняют. При потере соединения после записи ответ уже может быть
сохранён: обновите переписку перед повторной отправкой. Трассы инструментов
живут только на странице; источники восстанавливаются после перезагрузки.

HTTP API демонстрационный, без учётных записей и разграничения доступа между
операторами. Он публикует только учебные данные; реальную CRM нельзя подставлять
в этот API без отдельной реализации аутентификации и авторизации оператора.

## Проверка

```bash
npm run test:support
npx tsc --noEmit
```

Браузерный сценарий `tests/browser/support.mjs` запускается через Browser
Automation на `/day-33?ticket=SUP-101`, `SUP-102` или `SUP-103` при нужной ширине.
Он вызывает живую модель, проверяет MCP, источники, сохранение после обновления,
фокус, размеры элементов и отсутствие горизонтального переполнения.
