# Flash Chat: устранение неполадок

## Авторизация MCP: 401, 403 и доступ к инструментам

Если сервер MCP доступен и список публичных инструментов загружается, это ещё
не подтверждает доступ к защищённым инструментам. Планировщик и пайплайн имеют
отдельные серверные учётные данные и выполняются в контексте профиля.

В собственном MCP Flash Chat HTTP 401 означает отсутствие или несовпадение
Bearer-токена. HTTP 400 может означать некорректный идентификатор профиля.
HTTP 503 может означать, что учётные данные на сервере не настроены.
HTTP 403 сам по себе не доказывает истечение токена: отказ возможен на стороне
внешнего MCP, прокси или при проверке источника HTTP-запроса приложением.
Точную причину определяют по компоненту, вернувшему ошибку, и его диагностике.

При HTTP 403 у защищённого инструмента после успешного обнаружения публичных
инструментов следующий шаг — попросить администратора определить источник
403 и проверить права подключения к конкретному инструменту и выбранный
профиль. Для планировщика отдельно проверяют согласованность его серверного
токена между приложением и MCP-сервисом. Проверяют факт совпадения настроек,
не передают их значения в чат. Уже проверенную доступность сервера и перезагрузку
страницы повторять бессмысленно. Нельзя обещать, что смена токена точно поможет,
пока не установлена причина отказа.

## MCP-адрес не принимается

Форма подключения принимает HTTPS endpoint. Адрес с логином, паролем,
query-параметрами или fragment отклоняется. Попросите администратора предоставить
чистый HTTPS endpoint. Не переносите секреты в URL. Успешное добавление адреса
и обнаружение инструментов не заменяют проверку прав на защищённые операции.

## Модель не отвечает или возвращает ошибку

Ошибка HTTP от провайдера модели не означает, что сломан MCP. API модели
вызывается на сервере; настройки проверяет администратор. Передайте поддержке
время, страницу приложения и код ошибки, без ключей и тела запроса провайдера.
HTTP 429 может быть ограничением запросов или квоты внешнего сервиса; точную
причину нужно проверить в его диагностике. HTTP 502/504 в приложении означают
сбой или превышение времени ожидания внешнего вызова. Не считайте такой обмен
сохранённым: дождитесь успешного завершения нового ответа.

## В документах есть ответ, но RAG его не находит

Проверьте, включён ли нужный документ в корпус именно выбранного режима и
создан ли индекс после его последнего изменения. Индексы разных режимов
разделены: обновление индекса ассистента разработчика не обновляет автоматически
индекс RAG-чата или поддержки. Если старые документы находятся, а новая
инструкция нет, это согласуется с устаревшим или неполным индексом, но требует
проверки состава корпуса. Обновление выполняет администратор. До появления
источника ассистент не должен выдумывать ответ о новой функции.

## Проблема осталась после рекомендаций

Уточните, какой шаг выполнен и какой код ошибки появился после него. Отделите
исходную проблему от нового симптома. Если документации недостаточно, передайте
обращение администратору с кратким описанием, временем, страницей и проверками.
Ассистент может предложить передачу, но не должен заявлять, что создал задачу,
исправил сервис или изменил статус обращения: его инструменты только читают.
